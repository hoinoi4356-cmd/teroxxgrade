# RUSTGRADE

Клон rustgrade.com — маркетплейс предметів Rust з апгрейдером. Вхід **за
власним паролем**, без Steam OAuth. Грається з подвійного кліку по
`index.html`: жодного `npm`, `node` чи сервера не потрібно.

Каталог — **справжні предмети Rust зі Steam Community Market**: реальні назви,
реальні ринкові ціни в USD, реальні іконки скінів. Усього **4 166 предметів**.

Онлайн-версія на Render із спільним лідербордом: <https://teroxxgrade.onrender.com>

---

## Запуск

```
index.html        # двічі клацнути — і грати
```

Відкриється `file:///.../Default%20Project/index.html`. Нічого встановлювати
не треба.

Якщо хочеться **спільний лідерборд** (усі гравці з усіх браузерів в одній
таблиці), запускається той самий сайт із сервером:

```
node server.js    # http://localhost:3000
```

Без сервера сайт працює як завжди, просто таблиця лідерборду показує лише
акаунти цього браузера.

## Каталог: справжні предмети Rust

Каталог **не вигаданий**. Він зібраний зі Steam Community Market для Rust
(`appid=252490`) і лежить у `assets/data/catalog.js` (~342 КБ).

Для кожного предмета зберігається:

| Поле      | Що це                                             |
|-----------|---------------------------------------------------|
| `name`    | справжня назва скіна (`No Mercy Revolver - E Class`) |
| `usd`     | справжня ціна продажу на Steam Market              |
| `cat`     | категорія, визначена за назвою                     |
| `rarity`  | рідкість, визначена за ціною                       |
| `bg`      | справжній колір тла предмета (`background_color`)  |
| `listings`| кількість пропозицій на Steam Market               |
| `img`     | `assets/img/skins/<id>.jpg` — справжна іконка      |

Формат запису мінімальний, щоб файл завантажувався швидко:

```js
["6TMcQ7eX6E0E5460781770","No Mercy Revolver - E Class",1295.38,"pistol","exotic","42413e",12]
```

Ціни — від **$0.140** до **$1295.38**, тобто від 1 400 до 12 953 800 TX.

### Як оновлювати каталог

1. Зібрати сторінки Steam Market (по 10 предметів на запит).
2. Прогнати `build.ps1` — він здедуплікує, категоризує, порахує рідкість
   і запише `assets/data/catalog.js` + список іконок.
3. Завантажити іконки — скрипт бере `128fx128f` із CDN Steam, накладає їх на
   колір тла предмета і зберігає JPEG (~4 КБ замість 13 КБ у PNG).

Усі скрипти лежать у `assets/tools/`.

## Валюта і ціни

Єдине місце для зміни валюти — `CURRENCY` на початку `assets/js/data.js`:

```js
const CURRENCY = { code: 'TX', name: 'TX', decimals: 0 };
```

Ціна в ігровій валюті — це **справжня ціна в USD помножена на курс**:

```js
const USD_RATE = 10000;   // $10.09  ->  100 900 TX
```

На картці під ціною показується справжня ціна в доларах, на сторінці деталей —
ще й підпис «Справжня ціна на Steam Market».

Рідкість походить із ціни (`RARITY_BY_USD` у `data.js`):

| USD        | Рідкість     |
|------------|--------------|
| < 0.30     | Звичайний    |
| < 1        | Непоширений  |
| < 5        | Рідкісний    |
| < 20       | Незвичайний  |
| < 75       | Епічний      |
| < 250      | Легендарний  |
| ≥ 250      | Екзотичний   |

Валюта **повністю внутрішня**: виведення в реальні гроші не реалізовано
і не передбачене. Кнопки «пополнити» немає.

## Звідки беруться гроші

Кнопки поповнення немає взагалі. Усього два джерела:

| Джерело               | Сума        | Умова                                    |
|-----------------------|-------------|------------------------------------------|
| Промокод              | **25 000**  | один раз на акаунт                      |
| Перегляд ролика власника | **5 000** × 4 | один раз за ролик на акаунт          |

Обидва — у розділі **«Профіль»**. Промокод вводиться вручну; ролик
відкривається на YouTube, і після перегляду сума падає на баланс.

**Як роздавати промокоди:**

1. Увійдіть за будь-яким паролем.
2. Відкрийте `#/admin` (пункт «Адмінка» є в меню) і введіть **пароль
   власника** — він один на весь сайт, лежить у `ADMIN_KEYS` у `data.js`.
3. Вкладка «Промокоди»: вкажіть суму, код або натисніть «Інший» для
   генерації, нотатку («для Івана з Discord») і опцію «один раз на акаунт».
4. Скопіюйте код і дайте його потрібній людині.

> Назва жодного промокоду **ніде не показується**: немає банерів, окремої
> сторінки, згадок у меню чи в підвалі. Є лише порожнє поле «Промокод»
> у профілі. У списку активованих кодів показується лише маска `T•••••`.

## Апгрейд

1. Оберіть свій предмет (з інвентаря або кнопкою «Купити» на маркетплейсі).
2. Задайте **ціль**: фільтр за відсотком підвищення (35 / 55 / 75%) і
   множником (X2 / X4 / X8) звужує список, з-поміж нього ви клацаєте той
   предмет, який хочете отримати. Шанс апгрейду видно прямо біля цілі.
3. Натисніть «Апгрейд». Колесо крутиться, звучить і зупиняється там, де випало.

Випадний предмет ціниться за формулою реальної статистики цієї цілі, тож
апгрейд на реально рідкісний предмет справді рідкісний. Але **весь ролл рахує
клієнтський `Math.random`**, який можна підкрутити в DevTools — це демонстрація
механіки, а не захищена гра.

**Коли бракує грошей**, колесо не помирає: кнопка лишається активною,
показує `Бракує N TX`, а клік веде в профіль за промокодом. Цілі, на які
грошей немає, гасяться і підписуються «Жодна ціль не по кишенці».

Виграш показується на весь екран анімацією `assets/img/win.gif`.

## Лідерборд

Таблиця показує **нік, аватар і скільки «вибито» за добу** — за вкладками
«сьогодні / вчора / тиждень тому».

* **Якщо сайт відкритий з диска** (`file://`) — сервера немає, тому таблиця
  показує лише акаунти цього браузера. Так і має бути: без сервера чужих
  акаунтів просто не існує.
* **Якщо сайт відкритий по http** (`node server.js` або Render) — рядок
  надсилається на `/api/report`, а таблиця показує **усіх** гравців. Сортування
  за «вибито», потім за підсумком, потім за балансом. Свої рядки підсвічуються
  тегом «це ви» і не дублюються.

Пароль акаунту на сервер **ніколи не потрапляє**: у ключі акаунта лежить
пароль, тож замість нього надсилається випадковий ід пристрою
(`rgx_pid` у `localStorage`), а на сервері рядок зберігається під
`sha1(ід)` — без можливості відновити ключ.

## Адмінка

`#/admin` — панель власника. Відкривається паролем власника з
`ADMIN_KEYS` у `data.js`:

```js
const ADMIN_KEYS = ['RG-QCUE-5YP3-Q93Y-R2MN'];
```

Це **не** пароль від акаунту. Ввівши його один раз, акаунт запам'ятовує
права, тож далі вводити нічого не треба — і ви можете користуватися
адмінкою з будь-якого комп'ютера й браузера, де зареєструвалися.

Що всередині:

* **Гравці й нарахування** — список усіх акаунтів браузера (аватар, нік, ключ,
  баланс, виграші/спроби, знайдені пасхалки) і кнопка «Нарахувати» з
  довільною сумою для будь-якого рядка.
* **Промокоди** — створення й видалення кодів із нотатками.

## Вхід і свої акаунти

Пароль **довільний** — це не обов'язково `RG-XXXX-XXXX-XXXX-XXXX`. Можна
написати «дракон», «Drakon 2010», «12345», будь-які літери, цифри та пробіли.
Мінімум 3 символи, максимум 32. Регістр має значення: `Дракон` і `дракон` —
це два різні акаунти.

**«Увійти»** — вводите свій пароль. Якщо акаунтів уже створювали в цьому
браузері, внизу з'являється список **«Мої акаунти»**: натисніть на рядок, щоб
увійти миттєво, без введення пароля.

Якщо ввести неправильний пароль, акаунт **не створюється** — показується
помилка з підказкою перейти на вкладку реєстрації. Так випадково не подаруєте
собі порожній акаунт через помилку в великій літері. Єдиний виняток: ключ
вигляду `RG-XXXX-XXXX-XXXX-XXXX` створює акаунт автоматично.

**«Створити акаунт»** — вводите ім'я і пароль (або залишаєте пароль порожнім і
тиснете «Ключ», тоді згенеруємо `RG-XXXX-XXXX-XXXX-XXXX`). Після цього пароль
показується великим блоком із кнопкою копіювання — **запам'ятайте його**:
відновити неможливо.

Слова `__proto__`, `prototype`, `constructor` заборонені як пароль: вони
ламають об'єкт сховища. Решта — будь-яка.

Акаунти не заважають один одному: їх можна скільки завгодно, перемикайтеся
кліком по рядку у списку. Кожен має свій баланс, інвентар, історію, аватар та
активовані промокоди.

Новому акаунту дається:

* стартовий баланс **10 000 TX** (`START_BALANCE` у `data.js`);
* стартовий інвентар — найдешевші предмети з основних категорій (4 700–8 100 TX),
  щоб було з чим апгрейдити.

Аватар можна завантажити в профілі — будь-яка картинка обрізається по центру
в квадрат 128×128 і зберігається як `data:`-URL разом з акаунтом.

> **Чесне застереження.** Паролі лежать у `localStorage` відкритим текстом —
> їх бачить будь-хто, хто відкриє DevTools на цьому комп'ютері. Для іграшки з
> друзями це нормально; для грошей — ні. Не вводьте туди пароль від пошти чи
> від справжнього Steam.

Стан зберігається у `localStorage`: `rgx_session`, `rgx_accounts`, `rgx_promos`,
`rgx_pid`. Ключ акаунта — це ім'я поля в об'єкті `rgx_accounts`, тому довільний
пароль може містити пробіли, апострофи та лапки без проблем.

## Файли

```
index.html                  оболонка + порядок скриптів
server.js                   нульова залежність: статика + /api/board + /api/report
package.json                тільки для Render ("start": "node server.js")
assets/css/app.css          уся стилізація
assets/data/catalog.js      справжні предмети Rust (генерований, 4 166 записів)
assets/img/skins/*.jpg      справжні іконки скінів (~16 МБ)
assets/img/win.gif          анімація виграшу
assets/js/data.js           валюта, курс, рідкості, категорії, промокоди, ключі
assets/js/store.js          localStorage, транзакції, апгрейд, промокоди, адмінка
assets/js/board.js          синхронізація лідерборда з сервером + офлайн-відкат
assets/js/ui.js             тости, модалки, картки предметів, святкування
assets/js/wheel.js          колесо і звук (Web Audio, 0 байт аудіофайлів)
assets/js/app.js            хеш-роутер і всі сторінки
assets/tools/               скрипти оновлення каталогу
```

Порядок скриптів у `index.html` важливий:

```
catalog.js → data.js → icons.js → store.js → ui.js → board.js → wheel.js → app.js
```

Скрипти звичайні (не ES-модулі) — Chrome блокує `type="module"` на `file://`.

Усі звуки синтезуються через Web Audio API, тобто жодного аудіофайлу немає.

## Деплой на Render

Сайт не може бути просто «Static Site», бо лідерборду потрібен сервер:

| Параметр         | Значення            |
|------------------|---------------------|
| Environment      | Node                |
| Build Command    | *(порожньо)*        |
| Start Command    | `node server.js`    |
| Publish directory| *(не потрібен)*     |

`npm install` не потрібен — у `server.js` немає залежностей.

Лідерборд пишеться у `data/board.json` у пам'яті інстансу Render.
Безкоштовний план Render має **епемерну файлову систему**: після нового
деплою або перезапуску таблиця очищається. Гравці просто з'являться в ній
знову, коли зайдуть на сайт.

## Чесні обмеження

* **Ролли апгрейду — клієнтський `Math.random`.** Це демонстрація механіки;
  будь-який, хто відкриє DevTools, може підкрутити результат. Для справжньої
  гри потрібен сервер із генератором імовірностей на сервері.
* **Промокоди живуть у `localStorage`** — це прихована адмінка для ручної
  роздаці, а не захищена система. Видалення даних браузера стирає коди.
* **Лідерборд на Render жив у пам'яті інстансу** і скидається при рестарті.
* **Немає бази ані реального обміну предметами між гравцями**, ані виведення
  валюти в гроші.
* **Ціни — знімок Steam Market на момент збору.** Вони не оновлюються самі;
  для свіжих цін треба прогнати `assets/tools/` ще раз.
